# 🤖 Kiko — AI Job Assistant

Добро пожаловать в wiki проекта **Kiko** — сервиса, который автоматизирует поиск работы: сам находит подходящие вакансии, объясняет, почему они подходят, и готовит отклик за пользователя.

## 🎯 Проблема и решение

**Проблема.** Поиск работы сегодня — рутина: соискатель вручную пересматривает сотни вакансий на HH.ru и других площадках, сложно быстро понять реальное соответствие вакансии опыту, а написание сопроводительного письма под каждую вакансию отнимает время и часто делается «для галочки».

**Решение.** Kiko автоматизирует весь процесс:
1. Сам собирает свежие вакансии из открытых источников.
2. Сопоставляет их с резюме и настройками пользователя.
3. Считает **Match Score** — процент соответствия вакансии профилю.
4. Генерирует **AI Summary** — краткое объяснение, почему вакансия подходит.
5. Пишет персонализированное **сопроводительное письмо** под конкретную вакансию.

Помимо подбора вакансий, платформа объединяет и другие инструменты автоматизации поиска работы — например, улучшение резюме под ATS-системы (адаптация формата, ключевых слов и структуры под автоматических парсеров резюме у работодателей), и другие функции по мере развития продукта.

## 🖥 Продукт: два интерфейса

Kiko доступен в двух форматах, работающих на единой базе данных и общей аналитической логике — это не два разных продукта, а два интерфейса к одной системе.

| Интерфейс | Назначение |
| :--- | :--- |
| **Telegram-бот** | Быстрый повседневный доступ, уведомления о новых подходящих вакансиях, листание карточек вакансий прямо в чате |
| **Веб-платформа** | Полноценный личный кабинет: загрузка/редактирование резюме, детальная настройка поиска, история откликов, расширенная аналитика по вакансиям и статистике отклика |

### Telegram-бот — экран вакансии

Листалка вакансий через inline-кнопки (◀️ / ▶️):

```
Название — Компания
Зарплата | Локация
Match Score: [████░░░░░░] 75%
AI Summary — почему подходит
[Подробное описание] [Сгенерировать сопроводительное] [Перейти к вакансии 🔗] [Следующая ➡️]
```

### Веб-платформа

- Личный кабинет с полным профилем и резюме
- Дашборд с потоком персональных рекомендаций и фильтрами
- История откликов и избранное
- Расширенное отображение аналитики (динамика Match Score, статистика по источникам вакансий и т.д.) — то, что неудобно показывать в чате бота

## 🧩 Функциональные модули

### Модуль пользователя (User Settings)
- Профиль: ID, username, имя, язык интерфейса
- Резюме: загрузка файла (PDF/Docx) + текстовое представление для анализа
- Конфиг поиска: навыки (список), грейд (Intern/Junior/Middle/Senior…), локация, тип занятости (remote/office/contract и др.)
- Доступен как через бота, так и через личный кабинет на сайте

### Модуль вакансий (Vacancies & Parser)
- Источники сбора данных: **HH.ru, Telegram-каналы с вакансиями, ряд карьерных сайтов** (список расширяем)
- Данные вытягиваются через официальные API источников, где это возможно, либо стандартным парсингом страниц — там, где API недоступен
- Общая таблица вакансий хранит: источник, внешний ID, заголовок, компанию, зарплату, локацию, описание, ссылку, даты создания/парсинга

### AI-Анализатор (Matching Engine)
Ядро системы. Алгоритм матчинга — не нативное сравнение ключевых слов, а составной скоринг: каждой вакансии присваиваются очки по множеству критериев (стек и ключевые технологии, грейд, локация, тип занятости, дополнительные навыки, формулировки требований и др.), которые в сумме формируют:
- **Match Score (0–100%)** — итоговый взвешенный скор по всем критериям
- **AI Summary** — короткий текст (3–4 предложения) о причинах совпадения
- **Cover Letter** — сопроводительное письмо, генерируемое на основе текста конкретной вакансии (для прохождения ATS/AI-фильтров работодателя) и профиля соискателя — его грейда, навыков и других характеристик

Результаты хранятся в связующей таблице между пользователем и вакансией, включая флаги «просмотрено» и «избранное».

## 🗄 Схема базы данных

| Таблица | Описание |
| :--- | :--- |
| `users` | Пользователи (Telegram ID как ключ), профиль, резюме |
| `user_settings` | Навыки, грейд, локация, тип занятости |
| `vacancies` | Все вакансии из парсера (глобально, по источникам) |
| `user_vacancies` | Связка пользователь ↔ вакансия: `match_score`, `ai_summary`, `cover_letter`, `is_seen`, `is_favorite` |

Схема уже реализована в виде миграций (PostgreSQL) и является общей для бота и сайта — единый источник истины для обоих интерфейсов.

---

## 🔄 Workflow (логика работы)

1. **Парсинг** — парсер кладёт новые вакансии в `vacancies`
2. **Скоринг** — анализатор берёт активных пользователей, сопоставляет их профиль с новыми вакансиями
3. **Запись** — для подходящих вакансий (score > 40%) создаются записи в `user_vacancies`
4. **Уведомление** — бот пишет пользователю о новых высокоматчинговых вакансиях
5. **Просмотр** — пользователь листает рекомендации в боте или открывает сайт для детального анализа и управления откликами

## ⚙️ Технологический стек

| Компонент | Технология |
| :--- | :--- |
| Основной backend | Go — центральный API, бизнес-логика, работа с БД |
| Telegram-бот (фронтенд №1) | Python |
| Веб-сайт (фронтенд №2) | JavaScript |
| Скрипты парсинга | Python или другой язык (уточняется в процессе разработки) |
| AI-модуль | Python; рассматриваются два варианта: обучение собственной опенсорсной модели либо использование Gemini по API-ключу |
| База данных | PostgreSQL |
| Сбор данных | Официальные API источников (HH.ru и др.) там, где доступны, либо стандартный парсинг страниц |
| Matching | Старт с TF-IDF / Cosine Similarity, с переходом на векторные эмбеддинги (Vector DB) по мере роста данных |

Оба фронтенда (бот и сайт) обращаются к единому Go-бэкенду и общей базе данных.

## 💡 Ценность продукта

- Экономит соискателю часы ручного поиска и фильтрации вакансий
- Даёт объяснимую рекомендацию (не просто скор, а понятное «почему»), что повышает доверие к системе
- Снижает барьер отклика: письмо уже готово, остаётся проверить и отправить
- Двойной интерфейс (бот + сайт) закрывает и быстрый повседневный сценарий, и глубокую работу с профилем/аналитикой
